1. Overview — two decoupled subsystems

The Factory carries the compilation cost (hours); the Assembler only selects ready-made binaries (seconds). The binhost is the boundary between them.

Factory

Heavy, slow compilation. Produces binpkgs in USE variations (multi-instance), published per arch.

Binhost

A graph of (CPV, USE) nodes — not an array. Two pools: build-pool (with transients) and publish-pool (finals only).

Assembler

Nearly instantaneous. --usepkgonly installs ready-made binaries and assembles the ISO. Immune to cycles.

2. Weekly release flow (cron: Sunday 00:00)

The critical decision is the toolchain-bump: a normal week reuses the trunk (fast delta); a toolchain bump rebuilds everything clean (--emptytree), with no residue.

The reproducibility pursued is of input (same input → same set of packages), not bit-for-bit. -march=native is banned; each arch uses an explicit -march.

3. Package Factory — build in phases

Each phase is its own ordered emerge, with the flavor's /etc/portage already applied. The ordering deterministically resolves the cycles of large packages.

4. Breaking a circular dependency (use_break)

A real cycle measured by pretend-resolve: libsdl2 → pipewire → ffmpeg → libsdl2. The break is curated manually per flavor: compile with the USE turned off, then turn it back on.

flowchart LR

    CUR --> BP["BREAK-PASS

    BP --> SP["SETTLE-PASS

    SP --> GC{"USE-aware GC"}:::dec
    GC -->|"transient"| PODA["prune (build-pool only)"]:::stop

The transient binpkg exists only to break the cycle and never reaches the ISO. binhost.gc() tells apart a flavor variant (keep all), an old version (keep-N) and a transient (prune).

5. Fork-point & binhost partitioning

The early phases depend only on the init. The per-desktop fork happens late — the trunk compiles once per init; only the desktop phase branches.

Per arch (physical)

Mandatory: a znver5 binpkg (AVX-512) does not run on v3. One tree per arch.

Per USE (logical)

multi-instance + BUILD_ID absorbs the flavor/init variations within each arch.

Shared cache

ccache/sccache are keyed by flags → safe across flavors without breaking container purity.

6. ISO Assembler — immune to cycles

A cycle is a build-time phenomenon. The Assembler navigates the multi-instance graph and extracts the flavor's slice by the final USE — all the complexity stays in the Factory.

Consistency requirement: the final USE of the Factory's settle-pass must be identical to the USE the Assembler resolves — otherwise --usepkgonly fails with no match.

7. Matrix of composable axes

A release is the tuple base + arch + flavor + init, resolved by deep-merge. The axes do not multiply naively (desktop ≈ flavor).
